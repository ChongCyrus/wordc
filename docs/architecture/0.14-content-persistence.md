# 0.14 内容持久化（SQLite content_kv）设计

> 分支 `internal/0.14-content-sqlite`（基于 0.12.0 内容备份）。目标：内容事实源从 IDB 迁到 SQLite，IDB 作为可重建缓存；不做一次性全量内容迁移到多表，先用通用 KV 降低风险。

## 1. 内容清单

### A. 内置不可变正文（**不进 SQLite**）
- 内置 decks 正文（`source=builtin` / `builtinKey`）
- 内置 words 正文：headword/音标/释义/例句/词组/tags/order/难度/词频等
- 由打包资源/IDB 重建；`ensureBuiltinDecks/Words` 可再生。

### B. 内置词可变 overlay（进 SQLite）
- `rootEtymology`、`rootEtymologyCheckedAt/Version`
- `userNotes`、`userMnemonics`
- `derivationMap`、`ncMeaningIds`、`rootMnemonic`
- `rareMeaningIds`、`rareCoreSenses`、`rareMarkCheckedAt/Version`
- `senseMnemonics`、`coreSenseExamples/Phrases/Overview`
- `hiddenMnemonicKeys`、`maimemoVocId`
- `updatedAt`

### C. 自定义内容（进 SQLite）
- 自定义 `decks` 元数据
- 自定义 `words` 全文（无 builtinKey/source!=builtin）
- `packs`、`packItems`、`contentRejects`
- 独立 `derivationMaps`（meta 前缀 `derivationMap:`）
- meta 内容：`userNote:`、`userMnemonic:`、`rootEtymology:`、AI 内容键

### D. 不入 content_kv
- 学习 facts：states/plans/review_logs/settings（已有表）
- 临时 UI/session/checkpoint meta
- 内置不可变正文

## 2. 写入口清单（需逐一接入）

### 内置 overlay
- `updateRootEtymology` / `saveRootEtymology` / `deleteRootEtymology`
- `applyRootEtymologyBundle`（AI 批量）
- 笔记/助记保存（词级/含义级 userNotes/userMnemonics）
- 引申图保存/删除（词级 derivationMap、meta derivationMap）
- rare meanings / rare core senses / checkedAt 更新
- core-sense mnemonics/examples/phrases/overview
- nc meanings / hidden mnemonic keys
- MaiMemo导入写 `maimemoVocId`/overlay
- AI 内容包 apply（只改 overlay）

### 自定义内容
- 新建/编辑/删除自定义 deck
- 新建/编辑/删除/导入自定义 word
- 词库导入（新 deck/merge）
- `packs` 创建/更新/apply/删除
- `packItems` upsert/status/删除
- `contentRejects` upsert/删除
- 内容包导入导出（迁移后）

### 备份/恢复
- 0.12 基线/增量生成、恢复：改为读 content_kv revision/updated_at
- 清空数据/删除 deck/word 级联：同时清 content_kv

## 3. Schema（DB_VERSION=3）

当前 user_version=2；0.14 升到 **3**。SQLite 只新增 `content_kv`，用 `schema_meta.content_revision` 记录内容 revision（不建 content_meta）。

```sql
CREATE TABLE content_kv (
  key TEXT PRIMARY KEY,
  kind TEXT NOT NULL,
  json TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  revision INTEGER NOT NULL,
  deleted INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_content_kv_kind_updated ON content_kv(kind, updated_at);
CREATE INDEX idx_content_kv_rev ON content_kv(revision);
CREATE INDEX idx_content_kv_updated ON content_kv(updated_at);
```

不再建 `content_meta`；当前内容 revision 存 `schema_meta`，key=`content_revision`，value_json=`{"rev":N}`。`contentWrite` 在同一 native tx 内写内容行并递增 `content_revision`。

`key` 规范：
- `deck:<id>`
- `word:<id>`
- `word-overlay:<id>`
- `pack:<id>`
- `pack-item:<id>`
- `content-reject:<id>`
- `meta:<key>`（derivationMap/userNote/userMnemonic/rootEtymology）
- tombstone：`deleted=1` + `updated_at/revision`（保留用于增量备份）

`schema_meta.content_revision` 记录当前内容 revision；每次 `contentWrite` native tx 内递增 revision。
内置不可变正文不进 content_kv。

## 4. 迁移 IDB → SQLite

1. 前置：完整备份（SQLite facts + IDB 内容）、schema v2→v3（新增 content_kv；content_revision 入 schema_meta）。
2. 扫描：
   - 内置 decks/words：只写 word-overlay（有 overlay 的）
   - 自定义 decks/words 全量
   - packs/packItems/contentRejects
   - meta 内容前缀
3. 分批 200/tx，写 `content_kv`，`source` 标记 `migrated`；计数：每种 type 数量、revision。
4. 校验：
   - 抽样 hash、计数与 IDB 一致
   - `schema_meta.content_revision` 写入
5. 成功后写 `data.contentWriteSource=sqlite`；IDB 保留为 cache，重建路径 `rebuildContentCacheFromSqlite`。

原生接口：`contentList(prefix/kind/fromRevision/toRevision/includeDeleted)`、`contentWrite(expectedRevision,entries,deletes)`（单事务 rev+1）、`contentGet(keys)`、`contentCounts`；单行 ≤1MB、单批 ≤500/8MB。
6. 失败：不切写源、content_kv 回滚/清空（备份恢复），IDB 保持事实源。

## 5. 增量备份改造

- 不再 `buildContentSnapshot` 全量扫描：
  - 基线和增量从 `content_kv` 按 `revision` 分页生成；
  - 增量：`where revision > baseRevision and deleted=0/1`，直接带 `json`，无需 diff/export。
- `backup.contentChain` 记 `baseRevision`、`lastContentRevision`。
- 链断/版本不匹配 → full-required，不尝试全量 diff。
- 恢复：按 key upsert/tombstone，单 SQLite tx；成功后重建 IDB cache。
- 0.12 快照 diff 保留只作为**迁移前旧基线**兼容/回退，不再作为主路径。

## 6. 风险 / 回滚

| 风险 | 缓解 |
|---|---|
| 写入口遗漏导致 IDB/SQLite 双源 | 逐入口清单测试；默认 fail-closed；诊断页展示 source |
| KV 大 JSON 单行（词/包） | 单条大小上限；pack 分条；避免 20MB 字符串 |
| 迁移中途 kill | 分批 tx + revision 推进；启动检测 `contentMigrationState` 重试/回退 |
| 内容恢复覆盖学习 facts | content 与 facts 分库表/分 tx；恢复不碰 states/plans |
| 旧 0.12 基线不兼容 | entitySetVersion/格式检查 → full-required；兼容只读 |
| 回滚 0.13 | 关闭 `data.contentWriteSource` 回 IDB；content_kv 保留但不用 |
| IDB cache 丢失 | 从 content_kv 重建；内置正文从资源重建 |
| 词库导入/MaiMemo导入 | 统一走 content write helper；测试双源零写 |

## 7. 测试清单

- 迁移：计数/hash/抽样；kill 后续跑；失败回退 IDB。
- 写入口逐项：写 SQLite 后 IDB cache 同步；IDB 不被单独写；失败回滚。
- 内置 overlay：root/笔记/AI 修改→content_kv→重启保留；内置正文不进 content_kv。
- 自定义 deck/word/导入：content_kv 计数；删除 tombstone。
- packs/packItems/contentRejects：增删改/apply。
- 增量：revision 边界、删除 tombstone、恢复后 hash=删除后；链断 full-required。
- 恢复：单 tx 失败旧库不变；IDB cache 重建一致。
- 回滚：切回 IDB 可读写、不双源。
- 性能：12k 内置词只存 overlay；增量只读变更行；基线分块。

## 8. 实施顺序

1. schema v4 + content_kv/helpers + 测试
2. IDB→SQLite 迁移 + 校验/回退
3. 写入口（overlay 优先，再自定义内容/包）
4. 读路径/cache 重建
5. 增量备份改 revision
6. 删除/清空/导入/MaiMemo
7. 回滚与诊断


## 9. native 接口定稿（0.14）
- `contentList { prefix?, kind?, fromRevision?, toRevision?, includeDeleted?, limit, offset, orderBy? }`
- `contentWrite { expectedRevision, entries:[{key,kind,json,updated_at}], deletes:[key] }` — 单事务校验 rev→upsert/tombstone→rev+1；冲突 `E_CONFLICT`。
- `contentGet { keys }`、`contentCounts {}`。
- schema v3；`content_kv` + `schema_meta.content_revision`；v2→v3 preflight 备份，失败保留 v2。
- 单行 ≤1MB、单批 ≤500 条/8MB；prefix 用范围查询，不用 LIKE。

## 9. schema v3 / 降级

- native DB_VERSION=3；JS `SQLITE_SCHEMA_VERSION=3`。
- v2 打开 → native onUpgrade v2→v3，先 `pre-v3-*` preflight 备份，新增 content_kv + schema_meta.content_revision。
- v3 DB 被旧 JS/旧 App 打开：
  - health `userVersion > SQLITE_SCHEMA_VERSION` → 明确错误 `E_DOWNGRADE`；
  - **不 drop/不删库**；提示升级 App 或恢复 v2 备份。
- 回退策略：
  - 仅当需要回 0.12 时，从 v3 preflight 的 v2 备份恢复（或 App 内回滚入口）；
  - content_kv 数据不兼容 0.12，不能直接复用。
