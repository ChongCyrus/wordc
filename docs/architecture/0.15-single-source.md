# 0.15：原生 SQLite 单一事实源收敛

状态：设计稿（0.14.x 发布后执行）

## 目标

原生 APK：

- SQLite 是学习 facts 与可变内容的唯一事实源
- IndexedDB 只做可丢弃读缓存
- 删除 `contentWriteSource` 长期双写/切换语义
- 保留一次性迁移工具，完成后不再需要用户选择

Web/PWA：

- IndexedDB 唯一事实源
- 不使用 SQLite

## 不变量

1. 同一平台任一时刻只有一个写源。
2. 写流程先提交事实源，再更新 cache；cache 失败只标 dirty。
3. cache 缺失/dirty 时从事实源重建，不能反向覆盖事实源。
4. 备份/恢复只认事实源；跨平台靠导出/导入。
5. 内置不可变正文仍来自打包资源/IDB seed，不写 content_kv。
6. 迁移/恢复失败必须 fail-closed，不能留下半提交。

## 阶段

### P1 一次性内容迁移（0.14 → 0.15）

- 0.15 首次启动检测 0.14 的 `contentWriteSource=idb`。
- 后台/显式执行 shadow → counts/hash 校验 → finalize → 切换 sqlite。
- 迁移前备份 content/facts；进度可见；失败保持 idb 可读并提示。
- 迁移完成写 `contentMigrationV15=done`，之后不再走 idb 内容写。
- 不做 0.12/0.13 内容迁移（0.14 已是 schema v3 基线）。

### P2 删除双写切换

- 删除 settings 中的 `data.contentWriteSource` 或使其只读/内部。
- 删除 DebugPage 的切换/finalize/回退按钮，改为只读状态与“重建缓存”。
- 保留 `rollbackContentWriteSource` 仅供回退包/故障恢复，不作为日常开关。
- 迁移函数保留内部调用。

### P3 恢复/导入一致性

- 恢复包导入不再把写源强制回 idb；sanitize 包内写源字段。
- 导入后：
  - 内容写 SQLite（原生）
  - cache 重建/同步
  - 不保留旧 content_kv live 行（全量替换或 tombstone 差集）
- stale 标记保留为故障保护，不应在正常导入路径触发。

### P4 Web/原生适配层

- 统一 repository 接口：
  - native adapter：SQLite + IDB cache
  - web adapter：IndexedDB
- 不在同一平台保留两个事实源分支。
- 备份格式统一；来源按平台选择。

### P5 验收

- 0.14→0.15 覆盖安装：进度/内容/自定义词库/AI 内容/overlay 完整。
- 迁移中断/kill：重启可恢复或保持 idb。
- 评分/内容写入性能 <500ms。
- 备份/增量/恢复 hash 一致。
- 回退包/E_DOWNGRADE 安全。
- Web 端 fresh/升级不出现 SQLite 依赖。
- 390/360 UI + 真机 smoke。

## 风险

- 迁移 5528 overlay 需要分批，避免启动卡死。
- 备份文件体积；迁移前必须 preBackup。
- 旧 DebugPage/自动化脚本依赖切换 API，需要迁移。
- 0.14 测试大量 mock；需补真实 v3 集成 smoke。

## 完成定义

- 原生 fresh/升级后 `contentWriteSource` 不再是用户概念。
- 只有 SQLite 事实源 + IDB cache 两条路径。
- 全量测试、四 gate、真机覆盖/重启、备份恢复通过。
