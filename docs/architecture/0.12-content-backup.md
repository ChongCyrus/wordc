# 0.12 内容快照增量备份设计

## 目标
非进度内容（词库/用户内容/引申图/词根/内容包）不做大规模迁移，改为**内容快照索引 + 增量实体**：
- 首次完整快照作为基线；
- 之后只传新增/修改实体 + tombstones；
- 基线/链断时回退做新完整快照，不阻塞学习事实备份。

## 快照
`src/data/content-snapshot.ts`
- 扫描非进度内容：
  - `decks`、`words`、`packs`、`packItems`、`contentRejects`
  - meta 前缀 `derivationMap:`、`userNote:`、`userMnemonic:`、`rootEtymology:`
- 每个实体生成 `{type,key,hash,updatedAt}`：
  - hash = fnv1a64(stable JSON)
  - key = 表主键
- 分页 `batchSize`（默认 200）、`shouldAbort` 可取消、只保留索引（不含实体正文），内存可控。
- 输出 `ContentSnapshotManifest`：
  `{format:'momo-content-snapshot-manifest',formatVersion:1,snapshotId,revision,createdAt,counts,entries}`
- snapshotId = fnv1a64(canonical entries)。

## 增量
`ContentIncrementPackage`：
```json
{
  "format": "momo-content-increment",
  "formatVersion": 1,
  "baseSnapshotId": "...",
  "baseRevision": 3,
  "newRevision": 4,
  "snapshotId": "...",
  "entities": [{"type":"words","key":"...","hash":"...","updatedAt":1,"data":{}}],
  "tombstones": [{"type":"words","key":"..."}],
  "checksum": "fnv1a64:..."
}
```
- 对比基线：新 key→entity；hash 变→entity；基线有当前无→tombstone。
- 增量只含变化实体；完整快照实体按需由上层提供/导出。

## 校准
- 校验 `baseSnapshotId === currentManifest.snapshotId`、`baseRevision === currentManifest.revision`、包 checksum。
- 不一致/链断 → 返回 `needsFullSnapshot=true`，不推进 revision。
- 失败不推进 revision；连续失败 N 次 → 降级完整快照。

## 设置
- `backup.autoContentEnabled` 默认 **false**。
- 开启时先完整基线，再增量；连续失败 N=3 降级完整。

## 本轮范围
只实现 1/2 + 短测；不接 UI/自动调度/上传。

## 本轮已实现（1/2/3）

- `exportContentEntities`：按快照索引分页 bulkGet 实体正文（decks/words/packs/packItems/contentRejects/meta），可取消。
- `buildContentBaselineFile` / `saveContentBaselineFile`：基线文件 `content-baseline-<revision>-<snapshotId>.json`；checksum。
- 链状态 meta `backup.contentChain`：`{baseSnapshotId,revision,sequence,needsFullSnapshot,consecutiveFailures}`。
- 连续失败 3 次 → `needsFullSnapshot=true`；成功后清零。
- 存储抽象 `ContentBackupStorage`；native `content-backups/` 原子写/manifest/list 由 arch 实现（当前 mock 测试）。
