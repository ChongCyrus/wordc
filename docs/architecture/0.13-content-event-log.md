# 0.13 内容变更日志（event log）设计

## 目标
在 0.12 快照+hash diff 之上，为内容写入口增加轻量事件日志，使增量备份可优先消费日志；日志不可用/缺口/不一致时回退全量 hash diff。**不把内容迁移 SQLite（0.14）**。

## 可回退原则
- 关闭 `backup.contentEventLogEnabled` 后完全退回 0.12 A：快照 diff + 增量包。
- 日志只加速，不是事实源；IDB 内容仍是事实。
- 日志写失败只标 `dirty`，不阻塞内容写入/学习。

## 模块边界
### `src/data/content-event-log.ts`（新增）
- `recordContentOp({type,key,op:'upsert'|'delete',hash?,updatedAt})`
  - 写 meta `contentEventLog` 环形缓冲（内存/IDB meta），分配递增 `seq`
  - 写失败：捕获并 `markContentLogDirty('write-failed')`，不抛给写入口
- `listContentOpsAfter(seq)` → `{ops, nextSeq, gap}`
- `getContentEventLogState()` → `{lastSeq, dirty, lastError, updatedAt}`
- `resetContentEventLog(baseSeq)`

### 写入口接入（最小侵入）
- 现有内容写服务处调用 `recordContentOp`：
  - decks/words/packs/packItems/contentRejects 的 upsert/delete
  - meta 内容前缀（userNote/derivationMap/rootEtymology/...）
- 不改变写事务语义；日志在事务成功后记录（避免回滚留脏日志）。
- 批量写合并为 N 条 op（上限分批）。

### 增量消费（`content-backup.ts`）
- `createContentIncrement`：
  1. 若 `eventLogEnabled && !dirty && state.lastSeq == chain.lastLogSeq` → 用 `listContentOpsAfter(chain.lastLogSeq)`
  2. 日志 op → 实体/tombstone；逐条应用 hash 校验
  3. 日志缺口/seq 跳跃/checksum 失败/实体缺失 → **fallback hash diff**
  4. fallback 也失败 → `mode:'full-required'`，不推进 revision
- 成功增量后写 `chain.lastLogSeq = newSeq`；只推进成功链。

## 失败与降级
- 日志写入失败：dirty，下一次增量直接 hash diff。
- 日志缺口/乱序：`needsFullSnapshot=false` 时 hash diff；无法 diff（基线缺失/校验失败）→ full-required。
- 连续 3 次增量失败 → 自动新完整基线（0.12 已有失败计数）。
- 学习写入绝不因日志失败而失败。

## 测试
- 日志写失败不抛、dirty。
- seq 缺口/乱序 → fallback hash diff 结果与 A 一致。
- 坏 checksum/实体缺失 → full-required。
- 关闭日志 → 行为与 0.12 A 一致。
- 链恢复仍只用 baseline/增量文件，不依赖日志。

## 发布
0.12.0 合并发布时 B 作为第二阶段；A rc 真机通过后再合入 B。默认 `backup.autoContentEnabled=false`、`backup.contentEventLogEnabled=false`。

## 0.12.0 实际收口（最小可用 + 完整回退）

- event log instrument 当前仅覆盖 **rootEtymology 保存/删除**（wordOverlay upsert）。
- notes/userMnemonic、AI apply、pack/packItem/contentReject、自定义 deck/word 导入**仍走 hash diff**；结果与 A 一致，只是不加速。
- `createContentIncrement` 输出 `source:'log'|'diff'`：
  - log：开关开启、未 dirty、seq 连续、实体 hash 匹配；
  - diff：日志不可用/缺口/关闭/校验失败。
- 日志写失败只 dirty；`backup.contentEventLogEnabled=false` 完整退回 A。
- 0.12.1 再扩写入口。
