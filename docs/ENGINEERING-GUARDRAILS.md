# 工程防御性编程守则（重要数据/备份/学习进度）

> 适用于：IndexedDB 写入、词库重种/导入、备份/恢复、检查点、学习评分、删除类操作。
> 原则：**默认会失败，失败必须可恢复；宁可拒绝操作，不可静默丢数据。**

## 1. 写操作

1. 多表写入必须在**单个 Dexie 事务**内；失败自动回滚。
2. 禁止 `table.clear()` / `where(...).delete()` 整段删除后再重写；改为 **diff**：
   - 先 upsert 新数据
   - 只删除新数据中不存在的 key
   - 删除时同步清理引用（plan/reviewLogs/state/session 快照）
3. 任何删除/清空/替换必须：
   - 先成功写一份可验证的备份
   - 备份失败 → 拒绝执行
   - UI 二次确认并说明影响
4. 写入幂等：重复执行不产生重复记录/不破坏已有数据。
5. 并发：破坏性写（seed/import/restore/clear/deleteDeck）与评分通过全局写锁串行；禁止嵌套加锁（死锁）。
6. 数据版本：seed/import replace/clear/deleteDeck 成功后 `data.epoch +1`；评分携带会话 epoch，变化时先修复词/plan 再重试。

## 2. 文件/备份

1. 备份必须**原子**：写临时文件（`.partial` 或唯一时间戳）→ 校验大小/JSON/checksum → 才登记为可恢复备份。
2. 禁止覆盖唯一的好备份；同日多次备份用时间戳文件，保留 N 份完整文件。
3. 0KB/半包/坏 checksum 不进入恢复列表；定期清理。
4. 恢复前强制预备份；恢复失败回滚，不能留空库。
5. 恢复超时必须真正中止后续写（每批次检查 abort），状态标记 failed 可重试。
6. 备份/恢复/检查点均写诊断日志（数量、原因、耗时、错误）。

## 3. 检查点

1. 学习状态检查点只含 states/plans/settings，不依赖 words。
2. 每次评分成功后 ≤2s 落盘；`pagehide`/`visibilitychange hidden`/退出学习 flush。
3. 检查点写 native 私有目录，不随 IndexedDB 被回收；轮换 latest+3。
4. 启动顺序：确保词库 → 若 states 为空则从检查点合并恢复 → 再跑其他预装/备份。
5. 清空数据必须同时清检查点；显式恢复备份后刷新检查点。
6. 检查点恢复合并策略：只补缺失/较旧数据，不覆盖较新；失败不写。

## 4. 失败与诊断

1. 所有重要路径失败要可观测：`diag.lastWordMutation`、checkpoint status、backup status、data epoch。
2. 提供「一键导出安全诊断包」（计数/epoch/检查点/备份/最近删除/存储状态）。
3. 空库/异常页提供恢复入口；绝不提供无备份的一键清空。
4. 用户可见错误必须说明：发生了什么、数据是否安全、下一步怎么做。

## 5. 验证

1. 重要路径除单测外必须有故障注入：中途抛错、强杀、超时、并发、坏包、0KB、配额不足。
2. 断言恢复前后计数（decks/words/states/plans/reviewLogs）与关键状态不丢。
3. 发布前：源码逐路径审计清单 + 连续多轮不同角度审查无新问题。
