# 0.10.0 数据安全总攻：进度不丢失 + 增量检查点 + 备份恢复审计（code145）

用户另一台手机（0.8.0）导入 auto-backup-2026-11-22 后学习 20 分钟，出现异常画面，返回后数据再次被清空；备份列表出现 0KB/11 份等异常。要求极尽审计与"万无一失"保险。

## 目标（硬性）

1. **任何单次评分都不允许丢**：评分成功即写入检查点（最多滞后 2 秒/1 次评分）。
2. **崩溃/重启后自动恢复**：启动时若 decks/words 存在但 states/plan 为空或明显少于检查点 → 自动恢复检查点（合并，不覆盖较新数据），toast 告知；不弹"学习进度异常"后不管。
3. **破坏性操作全部加保险**：
   - 恢复/替换导入/清空数据前，强制预备份并校验；
   - 恢复失败必须回滚，绝不能留下空库；
   - 禁止自动备份覆盖非空好备份（空库不备份）；
   - 0KB/坏备份不入列表、不可选；
   - 保留策略：7 份 + 最近 3 份检查点，pre-restore 也纳入上限。
4. **全源码审计**所有会 delete/clear/seed/restore 的路径，列出并修复风险。

## 数据（dev-data）

- 新格式 `momo-progress-checkpoint` v1：`{format,formatVersion,createdAt,counts,states,plans,settings}`（**不包含 words/decks**，体积小）。
- `exportProgressCheckpoint()` / `importProgressCheckpoint(text,{strategy:'merge'})`：
  - states 按 `lastReviewedAt` 取较新合并；plans 同日合并取较新；settings 只补缺；不删除、不写 words。
- `saveProgressCheckpoint()`：写入 native 私有目录 `checkpoint-latest.migration.json`（轮换 checkpoint-1/2/3），带 checksum；失败仅日志，不阻塞学习。
- 学习评分成功后调用（debounce 2s）；页面隐藏/退出学习时 flush。
- 启动恢复：`recoverProgressIfMissing()`：states=0 且 checkpoint 有 states → 自动导入；toast/report。
- 测试：评分→检查点写入；杀进程模拟→恢复 241 状态/plan；坏 checkpoint 不崩；并发写；空库不覆盖。
- 审计所有删除路径：seedOne/importMigration/clearAllData/restoreAutoBackup/ensureBuiltinDeckWords，输出 `docs/reports/data-integrity-audit-2026-11-23.md`。
