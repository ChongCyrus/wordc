# 0.5.0 任务书：筛选结果 → AI 生成数据（code124）

## 背景与问题

0.4.x 已有高级筛选器、索引集、AI 面板和生成任务记录，但缺少用户原需求的关键闭环：

1. 高级筛选执行后没有针对「筛选结果」的 AI 生成数据 / 临时复习入口。
2. 没有独立的 AI 生成数据页；只能从词库批量选择进入 AI 面板。
3. 生成任务只记录进度，没有保存目标词列表与类型配置，无法真正断点续跑。
4. 生成页没有按类型属性筛选（如本义助记「仅未标记不常考」）。

## 需求（用户原话对应）

> 在上述筛选之后，点击「AI 生成数据」按钮即可跳转至 ai 生成数据的页面。

> ai 生成数据页面支持：ai 生成各种数据（如例句、词组、词根缀源数据、引申图数据、含义助记、串联本义助记、本义助记、...）及相关常用配置，筛选逻辑也是采用「属性组取值的逻辑关系」的方法，具体有哪些属性可以根据具体数据类型合理设置、覆盖全面，例如对于生成本义助记而言可以有「是否已标记不常考」的属性。

> 且支持增量分批生成，价格预算，并发，继续，会存储进度，支持断点续跑、APP 再次打开还能找到相应记录来继续之前的生成，且支持记录的基本管理操作（命名，删除，...）。

## 索引集语义（本次明确）

索引集 = **筛选条件的可复用定义 + 保存当时命中的单词快照（wordIds）**。

- 保存时同时写入：filter、sort、direction、groupBy、deckId、`wordIds`（当前筛选全部结果）。
- 载入时：恢复条件/排序/分组，并把 `wordIds` 作为当时的索引集快照；操作（AI 生成 / 临时复习）优先使用快照。
- 数据变化后快照仍可复用；用户可重新执行筛选刷新快照。

## 实现范围

### 数据（dev-data）

- `GenerationJob` 增加 `targets`、`config`、`sourceWordCount`。
- `createGenerationJob` 持久化；`appendGenerationJobResult` 支持 cursor。
- `getGenerationJobPendingTargets(id)`、`resumeGenerationJob(id)`（返回 targets/config/cursor/resumable）。
- 旧 job 兼容：无 targets 不可续，提示重建。
- 索引集：`saveFilterSet` 持久化 wordIds；载入/查询返回快照。
- 测试：tasks 持久化/剩余/旧数据兼容；索引集 wordIds 往返。

### UI（dev-ui）

- 筛选结果底部操作条：`AI 生成数据（N）`、`临时复习（N）`、`保存索引集`；N=已选用量，未选用全部筛选结果。
- 新路由 `/decks/:deckId/generate` + GeneratePage：
  - 来源显示「高级筛选 N 词」；
  - 全屏复用 AI 生成能力；
  - 关闭返回筛选页。
- 索引集保存时带 wordIds；载入恢复条件+快照；保存索引集列表显示条件/词数。
- 按类型属性筛选（至少）：
  - 本义助记：仅未标记不常考；
  - 词根缀源：仅无词根数据 / 未标记不常考；
  - 例句/词组/助记：排除已有数据；
  - 显示筛选后目标数。
- 断点续跑：任务中心「继续」→ GeneratePage with jobId；从 cursor 跑剩余 targets；结果/失败写回；重启可续。
- 任务命名/删除/清理完成。

### QA 验收

1. 筛选选定词 → 底部「AI 生成数据（N）」→ GeneratePage 显示来源 N。
2. 索引集保存含 wordIds；重进/载入后仍能拿到同一批词（即使条件重跑结果变化）。
3. 任务创建后关闭页面/重启 App → 任务中心「继续」→ 只处理剩余 target。
4. 按类型属性筛选改变目标数（如仅未标记不常考）。
5. 390/360 无重叠；按钮不竖排。
6. 回归：高级筛选、AI 多对象、批量不常考、词根缀源导入导出、final/final2。
